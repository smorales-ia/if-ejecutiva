## Decisión de contrato (congelada)

El payload que la UI envía al webhook de SC01 es **snake_case**, sin excepciones.
El schema zod permanece en camelCase (idiomático JS); el Route Handler traduce
antes del POST. Airtable ya era snake_case y no se toca.

Consecuencia práctica: tras este delta, **cualquier `{{1.x}}` del blueprint es
literalmente una clave del JSON que emite el Route Handler**. Ya no hay dos
convenciones conviviendo dentro del escenario.

### A4 · `contactosVisita` → `contactos_visita` (3 puntos ejecutables)

Hallazgo no previsto en el plan original, que contaba 4 mappings camelCase.
**Son 5**, y el quinto tiene más de una referencia:

| Ubicación | Antes | Después |
|---|---|---|
| Router 16 · filtro de la ruta | `"a": "{{1.contactosVisita}}"` | `"a": "{{1.contactos_visita}}"` |
| Router 16 · nombre del filtro | `"contactosVisita existe"` | `"contactos_visita existe"` |

| Módulo 1 · interface | `"name": "contactosVisita"` | `"name": "contactos_visita"` |

**Por qué importaba renombrar los tres juntos**: si sólo se hubiera cambiado el
Iterator, el filtro del Router habría evaluado `exist` sobre una clave
inexistente → falso → **la rama de contactos no se ejecuta y no se crea ninguna
fila en `TX_ContactosVisita`, sin ningún error visible en Make**. Falla
silenciosa. Los 6 subcampos del Iterator (`nombre`, `telefono`, `email`, `rol`,
`orden_prioridad`, `estado_contacto`) ya eran snake_case y no se tocaron.

El label del módulo 17 (`"Iterator ContactosVisita"`) se dejó en PascalCase: es
un nombre de módulo, no una clave del payload, y sigue la convención del módulo
18 (`"Crear ContactoVisita"`).

## 2. Naturaleza del bloque `interface` (contexto para el import)

El webhook (módulo 1) **no tiene data structure adjunta**:
`metadata.restore.parameters.hook.data.editable = "true"`, es decir
*"Determine data structure automatically"*. Implicaciones:

1. **En runtime, Make acepta cualquier clave JSON del body**, esté o no
   declarada. Los renames no rompen nada por validación de esquema.
2. El bloque `interface` es un **fósil del último payload que SC01 recibió de
   verdad**, no un contrato que valide. Sólo alimenta el autocompletado del
   designer.
3. Ese fósil corrobora el diagnóstico de la auditoría: contenía `documentos[]`
   (que el Route Handler ya no envía) y **no** contenía `ejecutiva_clerk_id`,
   o sea que el último payload real que recibió SC01 es **anterior a la
   integración con Clerk**. Coherente con H1 de la auditoría: el formulario
   nunca llamó al backend.

Editarlo era opcional para el runtime; se hizo (A6) para que el designer de
Make no ofrezca claves muertas al reabrir el escenario.
